向量化证据（第四轮补充实测）
============================================================================
口径：g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0
手段：只读取编译器向量化诊断（-fopt-info-vec-*）与反汇编，**不修改任何交付源码**。
      为让诊断指向明确的函数、不被其它代码淹没，把两个核心循环各自单独放一个
      翻译单元（内容与 src/optimized.cpp、bench/baseline.cpp 中的核心循环逐字相同）。
采集时间: 2026-10-15T19:2x +0800

----------------------------------------------------------------------------
[1] 交付版核心循环（单遍扫描 + 无分支搬运）
----------------------------------------------------------------------------
$ g++ -O2 -std=c++17 -pthread -fopt-info-vec-all=stdout -c onlyloop.cpp -I src -o onlyloop.o

  onlyloop.cpp:7:31:  missed: couldn't vectorize loop
  onlyloop.cpp:12:19: missed: not vectorized: more than one data ref in stmt: *_13 = *r_28;
  onlyloop.cpp:13:11: note: ***** Analysis failed with vector mode V2DI
  onlyloop.cpp:3:13:  note: vectorized 0 loops in function.

  结论：谓词已改成无分支，但 GCC 仍拒绝向量化 —— 直接原因是"一条语句里有多个数据引用"
        （即 `output[m] = r; m += ok;` 这种写入位置数据相关的 24 字节拷贝），
        且 64 位整数比较的向量模式（V2DI）分析失败。
        **该函数被向量化的循环数 = 0。**

----------------------------------------------------------------------------
[2] 平台 baseline 核心循环（四段短路分支）
----------------------------------------------------------------------------
$ g++ -O2 -std=c++17 -pthread -fopt-info-vec-all=stdout -c baseLoop.cpp -I src -o baseLoop.o

  baseLoop.cpp:5:31:  missed: couldn't vectorize loop
  baseLoop.cpp:5:31:  missed: not vectorized: control flow in loop.
  baseLoop.cpp:10:25: missed: not vectorized: more than one data ref in stmt: *_12 = *r_21;
  baseLoop.cpp:3:13:  note: vectorized 0 loops in function.

  结论：带分支的版本多一条更硬的理由 —— `control flow in loop`。
        同样是 0 个循环被向量化。

----------------------------------------------------------------------------
[3] 放开优化级别与指令集：-O3 -march=native（AVX2）
----------------------------------------------------------------------------
$ g++ -O3 -march=native -std=c++17 -pthread -fopt-info-vec-all=stdout -c onlyloop.cpp -I src -o onlyloop3.o

  onlyloop.cpp:7:31:  missed: couldn't vectorize loop
  onlyloop.cpp:12:19: missed: not vectorized: more than one data ref in stmt: *_13 = *r_28;
  onlyloop.cpp:3:13:  note: vectorized 0 loops in function.

  结论：即使放开到 -O3 + AVX2，过滤循环**仍然**没有被向量化。
        同一命令下被向量化的只有 src/support.hpp:70（数据生成器，32 字节向量）与
        support.hpp:98（读文件路径）—— 生成与文件 I/O 按题目规定都在计时范围之外。

  参考：对完整 src/optimized.cpp 用同一条 -O3 -march=native 命令，src/ 下被向量化的
        位置仅有 optimized.cpp:220（命令行默认值初始化，SLP）、support.hpp:70（生成器）、
        support.hpp:81（写头部时的字节组装）、support.hpp:98（读文件）—— 全都不在计时区内。

----------------------------------------------------------------------------
[4] 交付二进制反汇编：内层循环逐条指令
----------------------------------------------------------------------------
（filter_single_pass 被内联进 filter_records，下为其内层循环）

  movdqu (%rdx),%xmm0                            ; 取一条记录的前 16 字节
  cmp    %rbx,%rcx ; setae %al                   ; 时间戳下界 → 写寄存器低字节
  cmp    %r11,%rcx ; setb  %cl                   ; 时间戳上界
  and    %ecx,%eax
  cmp    %r10d,0xc(%rdx) ; setae %cl             ; 延迟
  and    %ecx,%eax
  mov    0x14(%rdx),%ecx ; and %r8d,%ecx ; cmp %r8d,%ecx ; sete %cl    ; flags
  and    %ecx,%eax
  movups %xmm0,(%rcx)                            ; 写出前 16 字节
  mov    -0x8(%rdx),%r14 ; mov %r14,0x10(%rcx)   ; 写出后 8 字节
  add    %rax,%rsi                               ; 写指针 += 命中掩码（0/1）

  说明：cmp / setcc / and / add 全部是**标量**指令（谓词→掩码→推进写指针）；
        movdqu + movups 是 24 字节记录的**整体拷贝**，xmm 寄存器只当搬运筐用，
        一条指令只处理**一条**记录，不存在"一条指令同时处理多条记录"的向量运算。

----------------------------------------------------------------------------
[5] 手工 SIMD 原型（AVX2 intrinsics）的尝试与结论
----------------------------------------------------------------------------
做法：一次处理 4 条记录，谓词全部在向量里算
      （时间戳区间用 (uint64)(t-begin) < span 的无符号比较技巧 + vpcmpgtq；
        延迟用 vpsubd + vpcmpgtd；flags 用 vpand + vpcmpeqd），
      再用 movemask 取 4 位掩码、按位序标量写出以保持稳定顺序；
      字段用跨步载入（vmovq/vpinsrd/vinserti128）或一次 96 字节栈拷贝两种方式各试一版。

结论：**原型未能做到正确**（多轮尝试后仍与参考实现不一致：逐谓词定位显示时间戳路径
      完全一致，延迟与 flags 路径存在差异）。因此本文件**不给出**手工 SIMD 的加速比 ——
      用未通过正确性验证的代码测出的耗时数字没有意义。

可以确证、且不依赖该原型的判断：
  * 交付版的收益来自"消除数据相关分支"（消融实验：贡献 >95%），而不是"算得更快"；
  * 24 字节 AoS 布局下，三个字段分别落在非对齐偏移 +0 / +12 / +20，向量化必须先付
    "字段组装"（跨步载入 + 重排）的成本，而标量版每条记录只需 1 条 movdqu；
  * 写成 24 字节/条时，命中记录的存储开销两边**相同**（都是 16B+8B 两条 store），
    SIMD 省下的运算时间填不到这里；
  * 因此"手工 SIMD 能带来可复现、可验证的净收益"这一主张**目前没有证据支持**，
    已在 REPORT.md 第 3.6 节如实记录为"尝试过、未能验证"。

复现命令（只读，不改动交付文件）：
  g++ -O2 -std=c++17 -pthread -fopt-info-vec-all=stdout -c onlyloop.cpp -I src -o /tmp/onlyloop.o
  objdump -dC --no-show-raw-insn bench/optimized | sed -n '/<filter_records/,/^$/p'
  （onlyloop.cpp / baseLoop.cpp 为本次诊断临时拆出的单循环翻译单元，已在文件头说明来由）
